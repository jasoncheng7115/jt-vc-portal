會議在手，主權我有Own your meetings, own your data

搭配 Jitsi Meet 基底的開源視訊會議系統，打造 Webex/Zoom 風格的會議入口，但一切由你掌控：多帳號 / 角色 / 2FA、預約、大廳、完整稽核與 SIEM 外拋。連線模式支援 8x8 JaaS（雲端託管）或自建 Jitsi Meet，一鍵切換。An open-source meeting portal for Jitsi Meet–based video conferencing — a Webex/Zoom-style front door that stays entirely under your control: multiple accounts / roles / 2FA, scheduling, lobby, full audit logging and SIEM forwarding. Connect to 8x8 JaaS (cloud-hosted) or a self-hosted Jitsi Meet and switch between them with one click.

8x8 自 2018 年起為 Jitsi / Jitsi Meet 的開發與維護公司；8x8 JaaS（Jitsi as a Service）即其官方雲端託管的 Jitsi 服務。Since 2018, 8x8 has been the company developing and maintaining Jitsi / Jitsi Meet; 8x8 JaaS (Jitsi as a Service) is its official cloud-hosted Jitsi service.

Why

為什麼需要 jt-vc-portal？Why jt-vc-portal?

把會議邀請連結到處轉貼、沒有權限與記錄，難以管理也難以稽核。Meeting links passed around everywhere, with no permissions and no records, are hard to manage and impossible to audit.

沒有入口閘道時Without a gateway

  • 邀請連結散落各處，誰建的、給了誰無從追查Invite links scattered everywhere — no way to trace who created them or who received them
  • 來賓可任意進入，缺乏開放時段與身分控制Guests can walk in any time, with no time-window or identity control
  • 沒有登入與行為記錄，無法稽核或外拋 SIEMNo login or activity records, so nothing to audit or forward to a SIEM
  • 綁死單一雲端服務，難以切換或自建省成本Locked into a single cloud service, hard to switch or self-host to cut costs
  • 就算魔改 prosody 擠出帳號管理，設定繁瑣又難維護Even if you hack account management into prosody, it is tedious to configure and hard to maintain

用 jt-vc-portal 後With jt-vc-portal

  • 統一入口：主持人登入才能建會議室，行為全程稽核One front door: only signed-in hosts can create rooms, and every action is audited
  • 預約時段、來賓需具名、主持人在線上才放行Scheduled time windows, named guests only, and guests admitted only while the host is online
  • 多帳號 / 角色 / 2FA；登入記錄可外拋 syslog/CEF/GELFMultiple accounts / roles / 2FA; login records can be forwarded as syslog/CEF/GELF
  • 雙模式：8x8 JaaS 或自建 Jitsi Meet，一鍵切換不動程式碼Dual-mode: 8x8 JaaS or self-hosted Jitsi Meet, switched with one click and no code changes
  • 帳號 / 角色 / 權限網頁化管理，免碰 prosody 設定檔Accounts / roles / permissions managed on the web — no need to touch prosody config files
Features

核心功能Core features

企業會議入口需要的均已內建，零外部 PHP 套件。Everything an organization's meeting portal needs is built in — with zero external PHP packages.

雙連線模式Dual connection modes

8x8 JaaS（RS256 + kid）或自建 Jitsi Meet（HS256 / 免 JWT），管理介面一鍵切換。8x8 JaaS (RS256 + kid) or self-hosted Jitsi Meet (HS256 / no JWT), switched with one click in the admin UI.

會議室管理Room management

建立 / 進入、亂數命名、近期清單、一鍵複製邀請、QR Code 彈窗。Create / join, random room names, a recent-rooms list, one-click invite copy and a QR code pop-up.

預約時段Scheduling

設定開放時段；未到顯示翻頁時鐘倒數，主持人提前進入即自動放行。Set an open time window; before it starts guests see a flip-clock countdown, and are let in automatically if the host joins early.

Email 邀請Email invitations

填與會者 email，寄送含 .ics 行事曆的邀請信，可自訂主旨 / 內文範本。Enter attendee emails to send invitations with an .ics calendar file, using customizable subject / body templates.

來賓流程Guest flow

來賓需自填名稱才進場；非開放時段顯示等候 / 倒數 / 已結束頁。Guests must enter their name before joining; outside the open window they see a waiting / countdown / ended page.

大廳模式Lobby mode

建立會議室可選；主持人進場自動開啟，來賓需經主持人逐一允許才能進入。Optional when creating a room; it switches on automatically when the host joins, and each guest must be admitted by the host.

多帳號 / 角色 / 2FAAccounts / roles / 2FA

admin 看全部、host 只看自己建的；支援 TOTP 雙因素認證。Admins see everything, hosts see only the rooms they created; TOTP two-factor authentication supported.

完整稽核 + SIEMFull audit + SIEM

登入、建室、邀請、設定變更全記錄，可即時外拋 syslog / CEF / GELF。Logins, room creation, invitations and settings changes are all recorded and can be forwarded in real time as syslog / CEF / GELF.

外觀客製Customization

60 種 Jitsi 介面語言、22 種主題、站台名稱 / logo、登入頁路徑偽裝。60 Jitsi UI languages, 22 themes, custom site name / logo, and a disguised login-page path.

會議統計Meeting statistics

會議時長排行、尖峰同時人數與參與者進出時間軸；JaaS 模式另接 USAGE webhook 統計 MAU。Meeting-duration rankings, peak concurrent participants and a join/leave timeline per participant; in JaaS mode the USAGE webhook also tracks MAU.

錄影調閱（自建 Jibri）Recording browser (self-hosted Jibri)

串接 Jibri 主機錄影服務：線上列表 / 播放 / 下載 / 刪除、主機容量、保留政策（時間 / 容量 / 殘留）；主持人可調閱自己會議的錄影。Connects to the recording service on your Jibri host: list / play / download / delete online, disk usage, and retention policies (age / capacity / leftovers); hosts can access recordings of their own meetings.

Compare

怎麼選？8x8 JaaS 與自建 Jitsi MeetWhich one? 8x8 JaaS vs. self-hosted Jitsi Meet

兩種模式都能在管理介面一鍵切換、不必改程式，依團隊規模與維運能力選擇即可。Both modes can be switched with one click in the admin UI without code changes — pick based on your team size and operational capacity.

小團隊建議從 8x8 JaaS 起步：JaaS 提供免費 Dev 方案（每月 25 MAU 免費額度），免架站、免維運即可上線，最適合小團隊、試用與內部小規模使用；待規模成長再評估轉自建。Small teams: start with 8x8 JaaS. JaaS offers a free Dev plan (25 MAU free per month), so you can go live with no servers to build or maintain — ideal for small teams, trials and small internal use. Consider moving to self-hosting once you grow.

8x8 JaaS（雲端託管）8x8 JaaS (cloud-hosted)

適合：小團隊、想快速上線、不想維運伺服器。Best for: small teams who want to go live fast without running servers.

  • 免費 Dev 方案（25 MAU/月），小團隊幾乎零成本上線Free Dev plan (25 MAU/month) — small teams can go live at almost zero cost
  • 免維運：伺服器、JVB、錄影皆由 8x8 代管No operations: servers, JVB and recording are all managed by 8x8
  • 全球節點、品質穩定，幾分鐘即可開通Global nodes with stable quality, up and running in minutes
  • 缺點：依 MAU 計費，規模大成本上升；媒體經第三方雲端，需評估隱私 / 合規Downsides: billed by MAU, so costs rise with scale; media passes through a third-party cloud, so privacy / compliance must be evaluated

自建 Jitsi MeetSelf-hosted Jitsi Meet

適合：重隱私自主、中小規模、具維運能力。Best for: privacy and autonomy, small-to-medium scale, teams with ops capacity.

  • 完全自主掌控，媒體資料不出自家機房Full control — media never leaves your own infrastructure
  • 無 MAU 計費，規模越大反而越省No MAU billing, so the bigger you get, the more you save
  • 可深度客製、與內網整合Deeply customizable and integrates with your internal network
  • 缺點：需自行維運 Jitsi / prosody / jicofo / JVB；錄影搭配自建 Jibri；並發量大需擴充頻寬Downsides: you operate Jitsi / prosody / jicofo / JVB yourself; recording requires a self-hosted Jibri; high concurrency needs more bandwidth

什麼是 MAU？MAU（Monthly Active Users，月活躍使用者）指一個計費週期內「不重複」加入會議的人數——同一人多次開會只算一位。8x8 JaaS 以此計費（免費 Dev 方案每月含 25 位）；自建 Jitsi Meet 無此限制。本系統用量統計頁會依訂閱週期統計目前 MAU。What is MAU? MAU (Monthly Active Users) is the number of unique people who join meetings within a billing period — someone who joins many meetings still counts once. 8x8 JaaS bills by MAU (the free Dev plan includes 25 per month); self-hosted Jitsi Meet has no such limit. The usage page in this system tracks current MAU according to your subscription cycle.
Security

安全性：遵循 OWASP Top 10:2025 實作Security: built to OWASP Top 10:2025

從設計到部署逐項把關。Checked item by item, from design to deployment.

A01
存取控制Access control未授權頁回 404、會議室依擁有者隔離、CSRF token。Unauthorized pages return 404, rooms are isolated by owner, CSRF tokens.
A02
安全設定Security configuration關閉錯誤顯示與版本洩漏、安全標頭、敏感路徑拒絕存取。Error display and version disclosure disabled, security headers, sensitive paths denied.
A03
供應鏈Supply chain零外部 PHP 套件；前端 CDN 資源加 SRI 完整性驗證；映像建置時套用最新 OS 安全更新。Zero external PHP packages; front-end CDN assets use SRI integrity checks; the latest OS security updates are applied at image build time.
A04
加密Cryptographybcrypt 密碼、JWT 簽章、webhook HMAC、安全 session cookie。bcrypt passwords, signed JWTs, webhook HMAC, secure session cookies.
A05
注入Injection輸出跳脫、輸入清洗、Email header injection 防護。Output escaping, input sanitization, email header-injection protection.
A06
安全設計Secure design閘道式架構、預設安全（來賓須具名、主持人在線上才放行）、角色最小權限。Gateway architecture, secure by default (guests must give a name and are admitted only while the host is online), least-privilege roles.
A07
認證AuthenticationTOTP 2FA、fail2ban 登入鎖定（依真實來源 IP）。TOTP 2FA, fail2ban-style login lockout (by real client IP).
A08
資料完整性Data integritywebhook 以 HMAC 簽章驗證來源，並用 idempotency key 去除重複事件。Webhooks are verified with HMAC signatures, and duplicate events are dropped via idempotency keys.
A09
記錄與告警Logging & alerting完整稽核記錄 + 即時 SIEM 外拋。Full audit log + real-time SIEM forwarding.
A10
例外處理Exception handling失敗安全降級：讀取失敗回預設、寄信 / 外拋失敗不阻斷主流程、錯誤不外洩。Fail-safe degradation: read failures fall back to defaults, mail / log-forwarding failures never block the main flow, and errors are not leaked.

01

儀表板Dashboard

登入後的主控台：輸入會議室名稱即可一鍵建立或進入會議室，也能亂數產生會議室名稱。下方「近期會議室」清單會顯示每間是誰建立、何時進入、開了多久，以及預約 / 大廳 / 主持人在線上等狀態，所有操作全程稽核。The console you land on after signing in: type a room name to create or join a room in one click, or generate a random name. The "Recent rooms" list below shows who created each room, when it was joined and how long it ran, plus scheduled / lobby / host-online status — and every action is audited.

02

建立會議室Create a room

勾選「限定開放時段」即可設定會議開放時間並寄送含 .ics 行事曆的 Email 邀請；也能勾選「大廳模式」讓主持人逐一允許來賓進入。建立後立即取得邀請連結與 QR Code，可直接開始主持或先複製連結稍後使用。Tick "Limit to a time window" to set when the meeting is open and send email invitations with an .ics calendar file; tick "Lobby mode" so the host admits guests one by one. Once created you immediately get the invite link and QR code — start hosting right away or copy the link for later.

03

用量統計Usage statistics

數據中心一頁掌握使用狀況。兩種模式通用：會議場次與時長、本期會議時長時間軸、主持人排行榜、近 30 天活動折線圖。另有 JaaS 模式專屬的本期 MAU 用量與方案上限、各計費週期歷史趨勢，並可手動校正用量基準（自建模式則自動隱藏這兩項、頁籤改稱「會議統計」）。A single dashboard for how the system is used. In both modes: meeting count and duration, a meeting-duration timeline for the current period, a host leaderboard and a 30-day activity chart. JaaS mode only: current-period MAU against your plan limit and the historical trend across billing periods, with manual correction of the usage baseline (in self-hosted mode these two are hidden and the tab is called "Meeting statistics").

04

稽核記錄Audit log

登入登出、建立 / 進入會議室、寄送邀請、帳號與設定變更等行為全數留存。可依行為類型、關鍵字與日期範圍篩選，欄位標題可點擊排序，並即時外拋 syslog / CEF / GELF 至 SIEM。Sign-ins and sign-outs, room creation / joins, sent invitations, account and settings changes — everything is kept. Filter by action type, keyword and date range, click column headers to sort, and forward events in real time as syslog / CEF / GELF to your SIEM.

05

帳號管理Account management

支援多個主持人帳號與角色：admin 可看全部會議室與管理頁，host 只看自己建立的。每個帳號可設定顯示名稱、Email、啟用 TOTP 雙因素認證，並可隨時編輯或停用。Multiple host accounts and roles: admins see all rooms and the admin pages, hosts see only the rooms they created. Each account has a display name and email, can enable TOTP two-factor authentication, and can be edited or disabled at any time.

06

系統設定System settings

集中管理所有設定：連線模式（8x8 JaaS / 自建 Jitsi Meet）、SMTP 寄信、會議記錄保留天數、Log 外拋、站台名稱與 Logo，以及 22 種外觀主題，一頁搞定。All settings in one place: connection mode (8x8 JaaS / self-hosted Jitsi Meet), SMTP mail, meeting-record retention, log forwarding, site name and logo, and 22 visual themes — all on a single page.

07

來賓進入Guest entry

來賓憑邀請連結進入，須先輸入顯示名稱才能進場，進入會議時自動帶入該名稱。整個來賓流程都套用站台主題與品牌，與主持端體驗一致。Guests arrive via the invite link and must enter a display name before joining; that name is carried into the meeting automatically. The whole guest flow uses your site theme and branding, consistent with the host experience.

08

等候 / 倒數頁Waiting / countdown page

非開放時段時，來賓會看到優雅的翻頁時鐘倒數與會議起訖時間；一旦主持人提前進入，系統每隔數秒自動偵測並放行，來賓無需重整、不必苦等。Outside the open window, guests see an elegant flip-clock countdown with the meeting's start and end times. If the host joins early, the page detects it within seconds and lets guests in — no reloading, no waiting around.

09

錄影記錄Recordings

調閱自建 Jibri 主機產出的會議錄影：線上播放、下載、刪除，並顯示錄影主機磁碟容量與每筆的大小、長度、狀態。可依會議室 / 主持人 / 參與者搜尋，點任一列展開該場的參與者進出時間軸。權限分明——主持人只看自己主持會議的錄影，管理者可管全部；保留政策（依時間 / 容量 / 殘留檔自動清理）也在此一目了然。Browse meeting recordings produced by your self-hosted Jibri host: play online, download, delete, and see the recording host's disk usage plus each file's size, length and status. Search by room / host / participant, and click any row to expand that meeting's participant join/leave timeline. Permissions are clear-cut — hosts see only recordings of meetings they hosted, admins manage everything — and the retention policy (automatic cleanup by age / capacity / leftover files) is visible at a glance.

10

會議室自訂Room customization

自建 Jitsi Meet 模式專用的會議室介面客製：進入時是否靜音 / 關鏡頭、畫質上限、預設檢視（演講者 / 畫廊）、是否關閉「視訊省頻寬」自動降載，以及逐項勾選工具列要開放的功能（聊天、螢幕分享、舉手、錄影、虛擬背景、共享文件…）。所有設定都在進入會議時自動帶入 Jitsi，無需改動 Jitsi 設定檔。Meeting-UI customization for self-hosted Jitsi Meet mode: whether to join muted / with camera off, maximum video quality, default view (speaker / tile), whether to disable automatic "bandwidth saving" video downgrades, and which toolbar features to enable, item by item (chat, screen sharing, raise hand, recording, virtual background, shared documents…). Everything is applied to Jitsi automatically when joining — no Jitsi config files to edit.

11

錄製設定Recording settings

設定會議錄製者在與會者清單顯示的名稱，並串接自建 Jibri 主機的錄影調閱服務——填入服務 URL 與 token 後即顯示連線狀態與已註冊錄製器數，並附上增減錄製器的文件連結。錄影保留政策可依時間（保留 N 天）、容量（保留可用空間或總量上限）或殘留檔自動清理，預設全部停用以策安全。Set the name the meeting recorder shows in the participant list, and connect to the recording service on your self-hosted Jibri host — enter the service URL and token to see the connection status and number of registered recorders, with a link to docs on adding or removing recorders. Recording retention can clean up automatically by age (keep N days), capacity (keep free space or cap total usage) or leftover files, and is all disabled by default to be safe.

前端反向代理 HTTPS（建議）HTTPS via a reverse proxy (recommended)

系統對外為 :58189，正式環境建議前面再以 nginx 或 Apache 反向代理掛上 HTTPS。The app listens on :58189; in production, put nginx or Apache in front as a reverse proxy to provide HTTPS.

# nginx 範例
server {
    listen 443 ssl;
    server_name your-domain.com;

    # ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    # ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:58189/;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

系統以 X-Real-IP 取得真實來源 IP（fail2ban 鎖定與稽核用），請務必讓反向代理帶上此 header。公開上線資安重點：設定 JTVC_TRUSTED_PROXIES（逗號分隔 IP/CIDR）只採信可信代理的來源標頭，並以 -p 127.0.0.1:58189:58189 或防火牆限制容器埠只讓反代可達——否則攻擊者可偽造 X-Real-IP 繞過 fail2ban、污染稽核。留空＝相容模式（盲信標頭，須搭配埠隔離）。經 Cloudflare 時讓反代由 CF-Connecting-IP 帶入 X-Real-IP。完整 Apache 站台設定範例請見 GitHub README。The app takes the real client IP from X-Real-IP (for fail2ban lockout and auditing), so make sure your reverse proxy sends this header. Security essentials for a public deployment: set JTVC_TRUSTED_PROXIES (comma-separated IPs/CIDRs) so forwarded headers are trusted only from your proxies, and use -p 127.0.0.1:58189:58189 or a firewall so only the proxy can reach the container port — otherwise an attacker can forge X-Real-IP to bypass fail2ban and pollute the audit log. Leaving it empty = compatibility mode (headers trusted blindly; requires port isolation). Behind Cloudflare, have the proxy populate X-Real-IP from CF-Connecting-IP. For a full Apache site configuration example, see the GitHub README.
