Why

為什麼需要 jt-vc-portal？Why jt-vc-portal?なぜ jt-vc-portal なのか？

把會議邀請連結到處轉貼、沒有權限與記錄，難以管理也難以稽核。Meeting links passed around everywhere, with no permissions and no records, are hard to manage and impossible to audit.会議リンクがあちこちに転送され、権限も記録もない状態では、管理も監査もできません。

沒有入口閘道時Without a gatewayゲートウェイがない場合

  • 邀請連結散落各處，誰建的、給了誰無從追查Invite links scattered everywhere — no way to trace who created them or who received them招待リンクがあちこちに散らばり、誰が作成し誰に渡したのか追跡できない
  • 來賓可任意進入，缺乏開放時段與身分控制Guests can walk in any time, with no time-window or identity controlゲストがいつでも入室でき、公開時間や本人確認の制御がない
  • 沒有登入與行為記錄，無法稽核或外拋 SIEMNo login or activity records, so nothing to audit or forward to a SIEMログインや操作の記録がなく、監査も SIEM への転送もできない
  • 綁死單一雲端服務，難以切換或自建省成本Locked into a single cloud service, hard to switch or self-host to cut costs単一のクラウドサービスに縛られ、乗り換えやコスト削減のためのセルフホストが難しい
  • 就算魔改 prosody 擠出帳號管理，設定繁瑣又難維護Even if you hack account management into prosody, it is tedious to configure and hard to maintainprosody を改造してアカウント管理を無理やり実現しても、設定が煩雑で保守が難しい

用 jt-vc-portal 後With jt-vc-portaljt-vc-portal を導入すると

  • 統一入口：主持人登入才能建會議室，行為全程稽核One front door: only signed-in hosts can create rooms, and every action is audited統一された入口：ログインした主催者だけが会議室を作成でき、すべての操作が監査される
  • 預約時段、來賓需具名、主持人在線上才放行Scheduled time windows, named guests only, and guests admitted only while the host is online予約時間枠、ゲストは名前の入力が必須、主催者がオンラインのときだけ入室を許可
  • 多帳號 / 角色 / 2FA；登入記錄可外拋 syslog/CEF/GELFMultiple accounts / roles / 2FA; login records can be forwarded as syslog/CEF/GELF複数アカウント / ロール / 2FA；ログイン記録は syslog/CEF/GELF で転送可能
  • 雙模式：8x8 JaaS 或自建 Jitsi Meet，一鍵切換不動程式碼Dual-mode: 8x8 JaaS or self-hosted Jitsi Meet, switched with one click and no code changesデュアルモード：8x8 JaaS またはセルフホストの Jitsi Meet を、コードを変更せずワンクリックで切り替え
  • 帳號 / 角色 / 權限網頁化管理，免碰 prosody 設定檔Accounts / roles / permissions managed on the web — no need to touch prosody config filesアカウント / ロール / 権限を Web 上で管理でき、prosody の設定ファイルに触れる必要なし

什麼是 MAU？MAU（Monthly Active Users，月活躍使用者）指一個計費週期內「不重複」加入會議的人數——同一人多次開會只算一位。8x8 JaaS 以此計費（免費 Dev 方案每月含 25 位）；自建 Jitsi Meet 無此限制。本系統用量統計頁會依訂閱週期統計目前 MAU。What is MAU? MAU (Monthly Active Users) is the number of unique people who join meetings within a billing period — someone who joins many meetings still counts once. 8x8 JaaS bills by MAU (the free Dev plan includes 25 per month); self-hosted Jitsi Meet has no such limit. The usage page in this system tracks current MAU according to your subscription cycle.MAU とは？MAU（Monthly Active Users、月間アクティブユーザー）は、1 つの課金期間内に会議へ参加した重複しない人数です。同じ人が何度会議に参加しても 1 人として数えます。8x8 JaaS は MAU で課金され（無料 Dev プランは毎月 25 人まで）、セルフホストの Jitsi Meet にはこの制限がありません。本システムの利用統計ページでは、契約の課金サイクルに沿って現在の MAU を集計します。

        proxy_set_header X-Forwarded-Proto $scheme;
    }

系統以 X-Real-IP 取得真實來源 IP（fail2ban 鎖定與稽核用），請務必讓反向代理帶上此 header。公開上線資安重點：設定 JTVC_TRUSTED_PROXIES（逗號分隔 IP/CIDR）只採信可信代理的來源標頭，並以 -p 127.0.0.1:58189:58189 或防火牆限制容器埠只讓反代可達——否則攻擊者可偽造 X-Real-IP 繞過 fail2ban、污染稽核。留空＝相容模式（盲信標頭，須搭配埠隔離）。經 Cloudflare 時讓反代由 CF-Connecting-IP 帶入 X-Real-IP。完整 Apache 站台設定範例請見 GitHub README。The app takes the real client IP from X-Real-IP (for fail2ban lockout and auditing), so make sure your reverse proxy sends this header. Security essentials for a public deployment: set JTVC_TRUSTED_PROXIES (comma-separated IPs/CIDRs) so forwarded headers are trusted only from your proxies, and use -p 127.0.0.1:58189:58189 or a firewall so only the proxy can reach the container port — otherwise an attacker can forge X-Real-IP to bypass fail2ban and pollute the audit log. Leaving it empty = compatibility mode (headers trusted blindly; requires port isolation). Behind Cloudflare, have the proxy populate X-Real-IP from CF-Connecting-IP. For a full Apache site configuration example, see the GitHub README.アプリは X-Real-IP から実際の接続元 IP を取得します（fail2ban のロックアウトと監査に使用）。リバースプロキシが必ずこのヘッダーを付与するようにしてください。公開運用時のセキュリティの要点：JTVC_TRUSTED_PROXIES（カンマ区切りの IP/CIDR）を設定して信頼できるプロキシからの転送ヘッダーのみを採用し、-p 127.0.0.1:58189:58189 またはファイアウォールでコンテナのポートにリバースプロキシだけが到達できるよう制限してください。そうしないと、攻撃者が X-Real-IP を偽装して fail2ban を回避し、監査ログを汚染できてしまいます。空欄の場合は互換モード（ヘッダーを無条件に信頼するため、ポートの分離が必須）です。Cloudflare 経由の場合は、リバースプロキシで CF-Connecting-IP の値を X-Real-IP に設定してください。Apache のサイト設定の完全な例は GitHub README をご覧ください。
